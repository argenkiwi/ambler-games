# Program Specifications

A terminal game of 2048: the player slides the tiles on a four-by-four board left, right, up or down, and equal tiles that collide merge into one of double the value, scoring that value. The player wins by creating a 2048 tile, may keep playing after that, and loses when the board is full and no move can merge tiles. The player may then play another game.

## Nodes

### New Game
- Initial node of the application, and the start of every game.
- Clears the board, sets the score to zero and clears the win flag, then places two starting tiles in random empty cells.
- It always transitions to `SHOW_BOARD`.

### Show Board
- Prints the board as a grid with empty cells shown as dots and tile values right-aligned, followed by the current score.
- It always transitions to `READ_MOVE`.

### Read Move
- Asks the player for a move: L for left, R for right, T for up (top), B for down (bottom), or X to end the game. Upper and lower case count as the same letter, and surrounding spaces are ignored.
- If the input is not one of those letters, it says so and transitions to `READ_MOVE`.
- If the input is X, it transitions to `GAME_OVER`.
- Otherwise it stores the direction as the current `direction` and transitions to `APPLY_MOVE`.
- If input cannot be read, or has ended, the walk stops with an error.

### Apply Move
- Slides every tile as far as it will go in the current `direction`. Each pair of equal neighbouring tiles that collide merges into one tile of double the value, adds that value to the score, and takes part in no further merge during the same move. When a line holds several pairs, the pair nearest the wall in the direction of travel merges first, so a full line of four 2s becomes two 4s.
- If no tile moved or merged, it tells the player the move had no effect and transitions to `SHOW_BOARD`; no tile is spawned and the board is unchanged.
- Otherwise it transitions to `SPAWN_TILE`.

### Spawn Tile
- Places one new tile in a random empty cell: a 2 nine times out of ten, a 4 otherwise.
- It always transitions to `CHECK_END`.

### Check End
- Decides whether the game is over or has been won.
- If the board holds a 2048 tile (or higher) and the player has not yet been told, it sets the win flag and transitions to `WIN`.
- If the board has no empty cell and no two equal tiles side by side, it transitions to `GAME_OVER` as a loss.
- Otherwise it transitions to `SHOW_BOARD`.

### Win
- Announces that the player has reached 2048 and asks whether to keep playing for a higher score, accepting yes or no (or y or n, in any case).
- If the answer is yes, it transitions to `SHOW_BOARD`; the win is not announced again this game.
- If the answer is no, it transitions to `GAME_OVER` as a win.
- If the answer is neither, it asks again by transitioning to `WIN`.
- If input cannot be read, or has ended, the walk stops with an error.

### Game Over
- Prints the final board and the final score, and announces how the game ended: a loss because no moves remain, a win because the player chose to stop at 2048, or a quit because the player pressed X. A player who quit after having reached 2048 is counted as a win.
- It always transitions to `PLAY_AGAIN`.

### Play Again
- Asks the player whether to play another game, accepting yes or no (or y or n, in any case).
- If the answer is yes, it transitions to `NEW_GAME`.
- If the answer is no, it transitions to `GOODBYE`.
- If the answer is neither, it asks again by transitioning to `PLAY_AGAIN`.
- If input cannot be read, or has ended, the walk stops with an error.

### Goodbye
- Thanks the player and terminates the walk.

## Shared State

The shared state consists of:
- `board`: the four-by-four grid of cells, each empty or holding a tile value (a power of two).
- `score`: the total of all merged tile values in the current game.
- `direction`: the direction most recently entered by the player (left, right, up or down).
- `won`: whether the player has already reached 2048 in the current game.
- `ending`: how the game ended (loss, win or quit), used by the final announcement.
