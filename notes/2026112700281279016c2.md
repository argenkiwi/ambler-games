`ambler node --state` checks field types against every node in the project, not just the walk being built. 2048 wanted `board` (number grid) and `move` (direction), but t3 already declares `board: Board` and `move: number`, so generation failed. Workaround: give 2048 its own `Board` type in utils/game2048.ts (the string `Board` matches t3 textually) and name the field `direction` instead of the spec's `move`; the spec was updated to match. Expect the same when adding any new walk with common field names.
