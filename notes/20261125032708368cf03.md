As of Nov 2026 the TS `ambler walk` scaffolds walks/<name>.ts with an empty State, every node wired `{ onDone: null }`, and comma-separated `--edge` values glued into one id string; it adds no package.json script, and reports "Created specs/<walk>.md" while leaving an existing spec untouched. Treat its output as a skeleton: hand-write State (union of node States), the edges records, the import.meta.main initial state and the package.json run script, then let tsc catch mismatches. The help text (`ambler help walk`) describes the intended behaviour, not the current one.

Reported upstream: https://github.com/argenkiwi/ambler-ts/issues/29. Repeated `--edge` flags DO wire correctly; only the comma form is mangled. Related: `ambler node --state field` types reused fields as string, https://github.com/argenkiwi/ambler-ts/issues/30.
