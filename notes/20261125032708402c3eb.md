Nodes that read a line (rps-player-choice, kps-player-choice, t3-player-move) never loop internally: bad input prints an error and takes onInvalid/onError, which the walk wires back to the same node. A null from readLine (EOF) takes onEndOfInput, wired to STOP in rps/kps and to halt in t3. Before the 2026-11 migration these nodes looped inside on while(true), and null fell into the retry path, so piping input or Ctrl-D spun forever. Keep this shape for any new input node so walk tests can script input and every edge stays visible in the wiring.
